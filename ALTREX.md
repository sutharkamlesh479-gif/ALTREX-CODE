# ALTREX CODE Project Instructions

- Use strict TypeScript and keep privileged operations out of the renderer.
- Do not display simulated agents, models, test results, confidence, or health states.
- Every visible action must be backed by a capability or explain why it is unavailable.
- Preserve local-first privacy and require explicit consent before repository data reaches a new cloud provider.
- Use typed, versioned schemas at IPC and service boundaries.
- Create recoverable checkpoints before material repository changes once the checkpoint service exists.
- Run applicable typecheck, tests, build, security, and runtime verification before completing a milestone.
- Keep components modular, accessible, responsive, and consistent with `docs/UI_SPEC.md`.
- Preserve the official two-logo system: Logo A is product/application identity; Logo B is coding intelligence.
- Never redraw, recolor, swap, or replace the supplied ALTREX logos with generated or competitor marks.
